# SpanVouch v0.5.0 Experimental Evidence Design

**Status:** Approved direction, written for specification review

**Release theme:** Experimental Evidence

**Baseline:** SpanVouch v0.4.0, commit `b8141fa4646010dc02c174fa0ddc2765190ab2da`

**Content type:** Conceptual design specification

This specification defines the evidence-producing release that executes the existing IVAD experiment design against two independently operated model services. It preserves the v0.4 engineering and security closure while replacing the planned self-hosted Qwen deployment with a metered Alibaba Cloud Model Studio API.

## Goal

Produce reproducible, budget-bounded evidence for the IVAD protocol and publish only claims that can be traced from a paper table back to a frozen experiment configuration, approved run manifest, provider provenance, immutable result artifact, and analysis output.

The release must distinguish three properties that are easy to conflate:

- context isolation: the verifier does not receive hidden generator context;
- model separation: B4 and B5 use Qwen rather than the DeepSeek generator family;
- operator separation: Qwen is served by Alibaba Cloud Model Studio, independently of the DeepSeek API service.

Same-model prompt separation is useful for B3, but it must not be represented as independent cross-model evidence.

## Scope

v0.5.0 is one experimental-evidence slice:

- retain the preregistered B0-B5 comparison matrix across LangGraph and AutoGen;
- use DeepSeek for diagnosis generation and the B2/B3 verifier conditions;
- use Qwen through Alibaba Cloud Model Studio/DashScope for B4/B5;
- convert Qwen provenance from self-hosted vLLM/GPU identity to managed metered API identity;
- preserve manifest authorization, request caching, global budget accounting, canonical pricing files, immutable artifacts, and statistical analysis;
- run the three-repetition pilot before freezing the formal configuration;
- run the formal experiment only after pilot acceptance and a new explicit paid-run authorization;
- generate paper tables, figures, and claims from checked analysis artifacts;
- update the IVAD paper and public README only after the corresponding result artifacts exist.

## Non-Goals

The following are outside v0.5.0:

- completing the former Phase 6 workstream;
- building or leasing a self-hosted Qwen/vLLM GPU deployment;
- treating two prompts to one model as independent model evidence;
- adding more providers, model-routing policy, automatic provider fallback, or provider benchmarking;
- changing the IVAD mathematical protocol to fit observed results;
- weakening project authentication, signed audit exports, or other v0.4 controls;
- automatically submitting the paper to arXiv or contacting endorsers;
- making paid provider calls in CI or during ordinary local tests.

## Experimental Matrix

The matrix remains fixed and complete:

| Condition | Generator | Verification path | Question isolated by the condition |
| --- | --- | --- | --- |
| B0 | DeepSeek | None | Baseline without verification |
| B1 | DeepSeek | Deterministic IVAD rules | Value of deterministic verification |
| B2 | DeepSeek | DeepSeek with shared diagnosis context | Effect of a same-model critic with shared context |
| B3 | DeepSeek | DeepSeek with isolated evidence only | Effect of context isolation without model separation |
| B4 | DeepSeek | Qwen with isolated evidence only | Effect of context isolation plus model and operator separation |
| B5 | DeepSeek | Deterministic IVAD rules followed by isolated Qwen | Combined deterministic and semantic verification |

Every condition is executed for both `langgraph` and `autogen`, with the same frozen cases, seeds, prompt versions, decoding settings, and analysis policy. The pilot uses exactly three repetitions. The formal run uses a value from 5 through 20 selected under the checked-in freeze policy after pilot analysis; it is never silently increased after results are visible.

## Provider Decisions

### DeepSeek service

The existing DeepSeek managed API remains the generator and same-model verifier service. The configured model identifier is fixed as `deepseek-v4-flash`; its normalized endpoint hash, prompt version, decoding parameters, and canonical pricing identity are frozen before each authorized run.

### Qwen service

The Qwen verifier uses Alibaba Cloud Model Studio/DashScope's OpenAI-compatible chat-completions API. The initial model identifier is `qwen3-14b`; account availability is a preflight requirement, not a reason to substitute a different model silently. Qwen thinking is explicitly disabled with the managed API request field `enable_thinking: false` so the request shape matches the non-thinking DeepSeek comparison.

The Qwen service is metered by provider-reported token usage. No GPU lease, vLLM container digest, Hugging Face revision, local chat-template hash, dtype, or maximum model length is required for this path because those values do not identify a managed deployment controlled by Alibaba Cloud.

Managed APIs cannot expose a weight digest. Reproducibility therefore freezes all observable deployment identity and records the provider-reported response model. A response whose model identity conflicts with the approved configuration fails closed instead of being accepted as equivalent.

## Provenance Contract

Both live endpoints use one managed-service provenance shape:

```text
provider                 logical model provider: deepseek or qwen
service_operator         deepseek or alibaba-cloud-model-studio
model                    exact request model identifier
endpoint_class           chat-completions
deployment_type          managed-api
api_compatibility        native or openai-compatible
base_url_sha256          SHA-256 of the normalized runtime base URL
pricing                  canonical file hash, official source, effective date, currency
```

Credentials and raw authorization headers are runtime-only and are excluded from configurations, manifests, caches, ledgers, reports, logs, and exception text. The endpoint URL remains supplied at runtime; only its normalized SHA-256 identity is persisted in experiment artifacts. The official pricing source may be recorded because it is public provenance rather than a credential.

The checked-in pilot configuration must contain real provider identities and canonical pricing metadata before any paid run. Placeholder domains, synthetic hashes, example cloud regions, and self-hosted Qwen pins are rejected by release verification.

## Runtime Interface

The managed-provider composition uses these inputs:

```text
DEEPSEEK_API_KEY
SPANVOUCH_DEEPSEEK_BASE_URL
SPANVOUCH_PHASE5_DEEPSEEK_PRICING_PATH
SPANVOUCH_QWEN_API_KEY
SPANVOUCH_QWEN_BASE_URL
SPANVOUCH_PHASE5_QWEN_PRICING_PATH
SPANVOUCH_PHASE5_BUDGET_LEDGER_PATH
```

The vLLM-specific environment variables and `SPANVOUCH_PHASE5_GPU_LEASE_PATH` are removed from the v0.5 path. `.env.example` documents names only and contains no usable credential or local absolute path.

`OpenAICompatibleConfig` gains an explicit managed deployment identity. Experiment validation accepts a managed endpoint only when the service operator, exact expected model, endpoint class, and normalized base URL provenance are bound by the Phase 5 configuration. Existing smoke-only adapter behavior remains available for non-experiment use; smoke configuration cannot be promoted into an authorized experiment implicitly.

## Authorization and Data Flow

The paid path remains fail-closed:

```text
frozen cases + experiment config
        -> exact matrix manifest hash
        -> explicit PaidRunAuthorization
        -> runtime endpoint normalization and provenance comparison
        -> canonical pricing verification
        -> guarded provider request
        -> cache claim and global budget reservation
        -> provider response identity and usage validation
        -> immutable condition result
        -> statistical analysis
        -> generated paper assets and claims
```

Authorization is checked before credentials are read or persistent provider state is opened. A request is identified by the experiment, config, deployment provenance, case, diagnosis, condition, prompt, messages, and generation settings. Identical authorized requests reuse the cache; materially different requests receive a different identity.

Provider usage is charged to the existing global monthly CNY ledger. The monthly cap remains CNY 1,000, the pilot may consume at most 10 percent of it, and new calls stop at the configured 80 percent threshold. Qwen cost is calculated from canonical input and output token rates rather than a GPU lease record. Cache hits do not create a second charge.

## Failure Behavior

The live composition rejects the run before network access when any of the following is true:

- the paid-run authorization does not match the exact experiment and manifest;
- a required credential, endpoint, pricing file, or ledger path is missing;
- a base URL is malformed, embeds credentials, or hashes differently after normalization;
- provider, service operator, model, endpoint class, or deployment type drifts;
- the pricing file is non-canonical, stale relative to its approved identity, or names another endpoint;
- the projected request would exceed the pilot or monthly budget gate;
- the provider response omits required usage or reports an incompatible model;
- a cached response fails integrity validation.

There is no automatic cross-provider fallback. Falling back from Qwen to DeepSeek would change the experiment condition and is therefore an error, not a resilience mechanism.

## Experiment Lifecycle

### 1. Offline readiness

All unit, integration, security, artifact, statistics, and paper-asset tests pass without provider credentials. Configuration preflight confirms model identifiers, endpoint hashes, canonical pricing files, clean budget state, and absence of placeholder provenance.

### 2. Pilot

An operator creates and approves the exact pilot manifest, then runs three repetitions for every matrix cell. The run may resume from cache after interruption. Pilot analysis reports failure modes, coverage loss, token use, total cost, variance, and whether the formal freeze policy can be satisfied.

### 3. Formal freeze

Only pilot-defined choices permitted by `phase5-formal-policy.json` are applied. The resulting formal configuration receives a UTC freeze timestamp and self-authenticating SHA-256 hash. Prompt text, provider identity, cases, conditions, metrics, confidence level, bootstrap draws, Holm correction, and coverage-loss tolerance are fixed before the formal run.

### 4. Formal execution and analysis

A separate authorization binds the formal manifest. The run produces immutable condition results, audit records, budget records, aggregate statistics, confidence intervals, corrected comparisons, and paper-ready assets. Failed or missing cells remain visible; they are not discarded to improve the outcome.

### 5. Publication update

The paper results section, limitations, artifact references, and README evidence summary are generated or edited from the verified analysis outputs. Deterministic offline results remain labeled separately from live semantic results. Claims that are unsupported, underpowered, or contradicted by the formal output are narrowed rather than promoted.

## Module Changes

The implementation remains within existing boundaries:

- `src/spanvouch/evaluation/experiments/config.py`: managed deployment provenance and provider-specific validation;
- `src/spanvouch/adapters/models/openai_compatible.py`: managed OpenAI-compatible experiment identity and response-model validation;
- `src/spanvouch/evaluation/phase5_live_composition.py`: Qwen managed API composition and removal of GPU lease setup;
- `evals/configs/phase5-pilot.json`: real managed Qwen identity and request shape;
- `evals/configs/phase5-formal-policy.json`: unchanged preregistration bounds;
- `.env.example`: managed Qwen runtime inputs;
- focused tests under `tests/adapters/models/` and `tests/evaluation/`: provenance, composition, authorization, budget, request, and secret-handling behavior;
- `paper/source/sections/06_experimental_design.tex` and `07_results.tex`: updated only after verified experiment artifacts exist;
- `README.md` and `README.zh-CN.md`: reproducible experiment instructions and evidence summary after formal analysis.

The budget ledger may retain historical GPU lease types for backward artifact readability, but the v0.5 managed Qwen path neither creates nor requires GPU lease records. Removing unrelated legacy artifact readers is not part of this release.

## Testing and Acceptance

Implementation is test-first. Acceptance requires:

1. the pilot configuration validates both providers as managed services and rejects incomplete or mismatched identities;
2. Qwen experiment composition uses only the approved managed API variables and never requires vLLM or GPU lease inputs;
3. `enable_thinking: false` reaches the Qwen request in the approved OpenAI-compatible shape;
4. authorization is rejected before credentials, cache, or ledger state are accessed;
5. endpoint normalization accepts harmless trailing-slash/default-port differences and rejects credentials, query strings, fragments, or provenance drift;
6. canonical pricing drift, provider/model mismatch, missing usage, and response-model drift fail closed;
7. provider keys and authorization headers never appear in artifacts, ledgers, logs, cache identities, snapshots, or errors;
8. B0/B1 remain offline, B2/B3 use DeepSeek, and B4/B5 use Qwen with no fallback;
9. cache reuse and concurrent request claims prevent duplicate paid calls and duplicate charges;
10. the pilot and formal budget gates remain globally enforced across both providers;
11. all existing deterministic, security, storage, artifact, statistics, CLI, API, and container tests remain green;
12. Ruff, mypy, the coverage floor, wheel build, Compose validation, offline acceptance, and container smoke gates pass;
13. a paid smoke test and pilot run occur only under explicit manifest authorization and are not part of CI;
14. formal paper claims are introduced only after their source artifacts pass integrity and analysis verification.

## Release Criteria

v0.5.0 is releasable only when the managed Qwen implementation and all local/CI gates pass, the authorized pilot and formal runs are complete within budget, result artifacts are reproducible from their manifests, and the IVAD paper plus bilingual README agree with the verified evidence.

Local commits do not imply publication. Pushing the branch, updating `main`, creating a tag, publishing a GitHub release, or making paid API calls each requires the corresponding explicit approval and credentials.

## Follow-up Versions

Broader model families, replicated provider operators, longitudinal provider-drift monitoring, larger case sets, independent reproduction packages, and hosted experiment orchestration are candidates for later releases. They must not expand v0.5 before the six-condition evidence package is complete.
