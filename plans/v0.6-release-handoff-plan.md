# SpanVouch v0.6 Reproducible Release Handoff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an offline `spanvouch release verify` gate that proves the release metadata and required distribution files agree on one expected version before v0.6 publication.

**Architecture:** Keep verification pure and independent from the CLI. `spanvouch.release.verify` reads only the supplied repository root and returns a typed, deterministic report; `spanvouch.release.cli` formats that report and maps failure to exit code 1. The top-level CLI adds a lazy route so release verification does not import provider or experiment modules.

**Tech Stack:** Python 3.12, `tomllib`, Pydantic 2, existing canonical JSON helpers, argparse, pytest, Ruff, mypy, uv, GitHub Actions.

## Global Constraints

- The command is offline-only and must not read provider credentials or perform network I/O.
- The expected version must match `^\\d+\\.\\d+\\.\\d+$` and is supplied explicitly by the caller.
- Version sources are `pyproject.toml`, `src/spanvouch/__init__.py`, `CITATION.cff`, `README.md`, and `README.zh-CN.md`.
- Required regular files are `LICENSE`, `README.md`, `README.zh-CN.md`, `CITATION.cff`, `pyproject.toml`, `uv.lock`, and `src/spanvouch/__init__.py`.
- Failure reports contain only safe check names, file names, and static details; no file contents, absolute paths, environment values, or exception text.
- No new runtime dependency, provider, paid run, experiment condition, or IVAD claim is introduced.
- Existing v0.5 behavior and release artifacts remain byte-stable unless a focused test requires a documentation command addition.
