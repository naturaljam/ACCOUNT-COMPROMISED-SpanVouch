# SpanVouch v0.6.0 Reproducible Release Handoff Design

**Status:** Approved direction for implementation

**Release theme:** Reproducible Release Handoff

**Baseline:** SpanVouch v0.5.0, commit `e9da00ead8f3fb5789690df898812cca4f0652d2`

**Purpose:** Close the engineering loop around the completed DeepSeek-only formal evaluation without creating new scientific claims or paid-provider work.

## Goal

v0.6.0 adds one offline, deterministic release verification surface. A clean checkout can validate that its package metadata, citation metadata, bilingual README release links, and required distribution files agree on one semantic version before a release candidate is built or published.

The verifier is a delivery gate, not an experiment runner. It reads local files only, never reads provider credentials, never opens a network connection, never mutates the checkout, and never interprets a passing release check as evidence for H1-H5.

## Scope

- Add `spanvouch release verify` with human-readable and canonical JSON output.
- Validate one expected `MAJOR.MINOR.PATCH` version across `pyproject.toml`, `src/spanvouch/__init__.py`, `CITATION.cff`, `README.md`, and `README.zh-CN.md`.
- Validate the required release files exist and are regular files: `LICENSE`, `README.md`, `README.zh-CN.md`, `CITATION.cff`, `pyproject.toml`, `uv.lock`, and `src/spanvouch/__init__.py`.
- Add CI and contributor instructions for running the gate from a clean checkout.
- Keep v0.5 artifacts, DeepSeek-only scope, budget controls, and fail-closed analysis semantics unchanged.

## Non-goals

- No new model provider, model routing, fallback, or paid experiment.
- No rerun of the formal matrix and no change to B4/B5 policy status.
- No change to IVAD mathematics, statistical thresholds, or H1-H5 claim status.
- No new runtime dependency and no network-backed release lookup.
- No reintroduction of a `docs/` publication tree; project plans remain under the existing root `plans/` convention.

## Public Interface

### Command

```text
spanvouch release verify \
  --repo-root . \
  --expected-version 0.6.0 \
  [--json]
```

`--repo-root` defaults to the current directory. `--expected-version` is required so CI cannot accidentally verify whichever version happens to be present. `--json` emits one canonical JSON object and no human progress text.

### Python API

`spanvouch.release.verify` exposes:

```python
def verify_release(repo_root: Path, expected_version: str) -> ReleaseVerificationReport

class ReleaseCheck(BaseModel):
    name: str
    passed: bool
    detail: str

class ReleaseVerificationReport(BaseModel):
    schema_name: Literal["spanvouch.release-verification"]
    expected_version: str
    passed: bool
    checks: tuple[ReleaseCheck, ...]
```

Checks are ordered by the fixed verifier sequence, contain only safe file names and static details, and are serializable through the repository's canonical JSON helper. A missing file, malformed metadata, version mismatch, non-regular path, or mismatched README release URL produces a failed check and a non-zero CLI exit code.

## Verification Rules

1. Validate `expected_version` against `^\\d+\\.\\d+\\.\\d+$`.
2. Read `pyproject.toml` with `tomllib` and compare `project.name == "spanvouch"` and `project.version`.
3. Read `src/spanvouch/__init__.py` and compare the literal `__version__` assignment.
4. Read `CITATION.cff` and compare its top-level `version` field.
5. Require every occurrence of `releases/tag/v<version>` in both README files to use the expected version, and require at least one occurrence per file.
6. Require the seven release files listed above to exist as regular files.
7. Return a report with `passed == all(check.passed for check in checks)`; do not stop after the first failure so CI receives the complete local diagnosis.

The verifier must not print file contents, environment values, exception text, absolute paths, or URLs containing credentials. It may include stable details such as `pyproject.toml version matches` or `README.zh-CN.md release links match`.

## Architecture

The pure verifier lives in `src/spanvouch/release/verify.py` and has no CLI or process-global state. `src/spanvouch/release/cli.py` owns argument parsing and output formatting. `src/spanvouch/cli/main.py` adds only the lazy route `release verify`, preserving the existing import boundary. Tests use temporary synthetic repositories for mismatch cases and do not write to the checkout.

## Acceptance

- A clean v0.6 checkout returns exit code 0 and a report with every check passing.
- Each individual version source and required-file failure is covered by a focused test.
- Human output is concise; JSON output is canonical and deterministic.
- The command is runnable without provider credentials and without network access.
- CI runs the command after the locked package install and before the full test suite.
- Full pytest, Ruff, mypy, hash-constrained build, and Compose validation remain green.

## Follow-up Boundary

The v0.6 release closes the engineering delivery loop. Cross-model replication, new providers, larger formal samples, and changes to the IVAD claim policy remain separate future research or experiment work and do not block this release.
