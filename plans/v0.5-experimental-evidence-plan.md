# SpanVouch v0.5 Experimental Evidence Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

Goal: Replace the Phase 5 self-hosted Qwen experiment path with a fail-closed, metered Alibaba Cloud Model Studio OpenAI-compatible path while preserving the six-condition IVAD evidence workflow.

Architecture: Experiment provenance gains managed-service identity fields service_operator, deployment_type, and api_compatibility. The existing OpenAI-compatible adapter remains the transport boundary; the Phase 5 composition root owns environment names, URL-hash comparison, pricing validation, and budget wiring. The global budget ledger keeps legacy GPU-record readers for historical artifacts, but the managed Qwen path never creates or requires a GPU lease.

Tech Stack: Python 3.12, Pydantic 2, httpx, pytest/pytest-asyncio, Ruff, mypy, uv, existing SpanVouch manifests, cache, ledger, and artifact contracts.

## Global Constraints

- Qwen service operator is alibaba-cloud-model-studio; exact approved target model is qwen3.7-plus.
- DeepSeek model remains deepseek-v4-flash.
- B0/B1 are offline; B2/B3 use DeepSeek; B4/B5 use Qwen; no provider fallback.
- Qwen requests include enable_thinking: false.
- Required runtime names are SPANVOUCH_QWEN_API_KEY and SPANVOUCH_QWEN_BASE_URL; the managed path reads no vLLM or GPU-lease environment.
- Monthly budget remains CNY 1,000; pilot fraction remains 0.10; stop fraction remains 0.80.
- Credentials, authorization headers, raw provider responses, and secret-bearing URLs never enter persisted artifacts, logs, cache identities, or errors.
- Tests, CI, and ordinary local verification make no paid provider call.
- A model-directory preflight confirms qwen3.7-plus before an authorized paid run. An unavailable model remains a hard stop requiring explicit model approval.
- Paper and README result claims are updated only after verified pilot/formal artifacts exist.
