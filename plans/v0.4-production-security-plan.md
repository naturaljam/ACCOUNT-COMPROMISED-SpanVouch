# SpanVouch v0.4.0 production security implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add project isolation, mandatory API-key authentication, role-based authorization, signed audit exports, and v3-to-v4 recovery-safe persistence to SpanVouch.

**Architecture:** Keep the existing deterministic diagnosis and review services intact behind typed `Principal` and `ProjectContext` inputs. Add focused security, project, and audit modules; extend the shared SQLite schema transactionally; enforce policy at FastAPI boundaries and project predicates in repositories. Reuse `ArtifactManifest` for signed audit bundles and expose the same management contracts through an HTTP API and thin CLI client.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLite WAL, `hashlib.scrypt`, `cryptography` Ed25519, httpx, argparse, pytest, pytest-asyncio, pytest-cov, Ruff, Mypy, uv, Docker Compose.

## Global Constraints

- Work only on `codex/v0.4-production-security`, never directly on `main`.
- Do not push or create a GitHub release without separate user approval after all gates pass.
- Keep `/health` and `/ready` public; every other HTTP route requires a valid non-expired, non-revoked API key.
- Store API keys only as a salted scrypt digest, non-secret prefix, optional project, roles, status, timestamps, and expiry.
- Permit system-scoped keys only for the `admin` role; require every other key to bind exactly one project.
- Accept `X-SpanVouch-Project` only from an authenticated system administrator and record the selected project in its audit event.
- Use `hashlib.scrypt(n=16384, r=8, p=1, dklen=32)` and constant-time digest comparison.
- Use Ed25519 through the pinned `cryptography` dependency; offline verification must not need a database or provider credentials.
- Add `project_id` to every trace, diagnosis, review case, immutable event, and audit export.
- Migrate schema v3 to v4 in one transaction and assign existing data to `default`.
- Preserve deterministic diagnosis, review transitions, idempotency, optimistic concurrency, offline evaluation, and the current `92` percent coverage floor.
- Never log, persist, or return plaintext API keys or signing private keys.
- Use TDD for every production behavior: write one failing test, run it, implement the minimum, run the focused test, then commit.
