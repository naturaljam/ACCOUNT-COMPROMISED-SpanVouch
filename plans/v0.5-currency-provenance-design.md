# SpanVouch v0.5 Currency Provenance Design

**Status:** Approved approach A on 2026-07-31

**Goal:** Preserve each provider's official native-currency price while keeping the Phase 5 global budget ledger in CNY with a reproducible, conservative conversion.

## Problem

The managed-provider implementation currently requires every pricing file to use CNY. Alibaba Cloud Model Studio publishes the selected China-region Qwen price in CNY, but DeepSeek publishes the direct `deepseek-v4-flash` API price in USD. Copying the USD numbers into a CNY file would understate cost and make the experiment provenance false.

The pricing model also represents one input rate. That is acceptable only when the frozen rate is conservative for every request admitted by the experiment. DeepSeek therefore uses the cache-miss rate for all input. Qwen uses the non-discounted `0 < Token <= 256K` tier and rejects a request before network I/O when its conservative input estimate exceeds that tier.

## Considered Approaches

1. **Native price plus canonical conversion provenance (selected).** Keep official native prices, freeze an official reference rate and a conservative CNY reserve rate, and hash all inputs. This preserves provenance and protects the CNY budget.
2. **Manual CNY upper bound.** Convert outside the system and store only a CNY estimate. This is simpler but cannot reproduce the conversion and obscures the provider's official price.
3. **Account-statement billing only.** Derive CNY cost after the provider charge. This cannot reserve budget before network I/O and is unavailable for a preregistered pilot.

## Pricing Contract

`Pricing.currency` accepts `CNY` or `USD`. Existing CNY files remain valid without a conversion block. A USD file must contain a `conversion` object with:

- `budget_currency`: exactly `CNY`;
- `reference_cny_per_native_unit`: the reproducible cross-rate before safety margin;
- `reserve_cny_per_native_unit`: the rate used by all reservations and recorded cost estimates;
- `buffer_fraction`: `0.05` for this experiment;
- `rounding_increment`: `0.10` CNY;
- `effective_date`: the reference-rate observation date;
- `source_urls`: the exact first-party rate-series URLs used in the cross-rate.

Validation recomputes the reserve rate as the reference rate multiplied by `1 + buffer_fraction`, rounded upward to `rounding_increment`. A missing conversion for USD, a conversion on CNY, a non-CNY budget currency, an empty source list, or a mismatched reserve rate is rejected before persistent state or network access.

`Pricing.max_input_tokens` is optional. When set, `provider_cost` rejects a larger input count. `GuardedProvider` already computes a conservative UTF-8 byte-count estimate before its network call; the pricing-tier check runs against that estimate during reservation. Actual provider usage is checked again after the response.

`provider_cost` continues returning a CNY decimal. It first computes native-currency token cost, then applies the validated reserve rate for USD or identity conversion for CNY, and finally rounds to the existing six decimal places. The ledger and downstream artifact contracts therefore remain CNY-only.

## Files And Boundaries

- `src/spanvouch/evaluation/experiments/budget.py` owns currency conversion validation and CNY cost calculation.
- `src/spanvouch/evaluation/experiments/config.py` allows provenance currency `CNY` or `USD` while retaining exact pricing-file hash checks.
- `src/spanvouch/evaluation/phase5_live_composition.py` continues loading canonical files and rejecting any provenance drift.
- `evals/configs/phase5-deepseek-v4-flash-pricing.json` freezes the direct DeepSeek price and ECB conversion.
- `evals/configs/phase5-qwen3.7-plus-pricing.json` freezes the conservative Model Studio China-region price.
- `evals/configs/phase5-pilot.json` receives the new hashes, source URLs, effective dates, and native currencies.
- `tests/evaluation/experiments/test_budget.py` covers conversion validation, rounding, CNY identity behavior, tier rejection, and conservative cost.
- `tests/evaluation/experiments/test_config.py` covers USD provenance acceptance and currency drift rejection.
- `tests/evaluation/test_run_phase5_live.py` proves invalid conversion and over-tier input stop before provider I/O.

No credential, workspace URL, raw response, account balance, or billing statement is added to a tracked file. The workspace-specific Qwen URL hash remains a separate local freeze step after the user configures the endpoint.

## Failure Rules

The paid path stops before provider I/O when:

- the pricing file is not canonical JSON;
- its SHA-256, provider, model, native currency, source URL, or effective date differs from pilot provenance;
- USD conversion provenance is missing or mathematically inconsistent;
- a CNY price contains a foreign-exchange conversion;
- the conservative pre-call input estimate exceeds the frozen price tier;
- the resulting reservation crosses the pilot or monthly stop threshold.

The path stops after a response and records no successful cache result when reported usage violates the frozen tier. The existing over-reservation stop remains active if provider-reported usage produces a larger cost than reserved.

## Verification

Implementation follows red-green-refactor. Focused tests must first fail for the missing USD conversion behavior, then pass after the minimal model and calculation changes. Completion requires the focused pricing, configuration, live-composition, provider, and budget tests; full pytest; Ruff; mypy; canonical JSON verification; wheel build; and `git diff --check`.

No pilot or formal result claim is allowed until a separately authorized paid run produces verified artifacts.
