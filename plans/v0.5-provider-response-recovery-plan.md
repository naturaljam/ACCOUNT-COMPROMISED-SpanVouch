# SpanVouch v0.5 Provider Response Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover the interrupted DeepSeek candidate run with schema-aware cached
responses, complete provider-cost accounting, and verified per-cell resume while
preserving the frozen experiment manifest.

**Architecture:** A generic JSON-model response policy sits at the provider response
seam, with diagnosis and semantic-verifier adapters supplying their exact draft
schemas. `GuardedProvider` settles every returned response before persistence and
records content disposition separately from charge disposition. The candidate
repository verifies all existing content-addressed cells before an explicit resume
skips them.

**Tech Stack:** Python 3.12, Pydantic 2, SQLite, asyncio, pytest/pytest-asyncio,
Ruff, mypy, uv, existing SpanVouch canonical JSON, cache, ledger, and artifact
contracts.

## Global Constraints

- Do not change candidate manifest
  `30224fda50910897f388773bc7e2bd0328ac023dfd6a990c821120c4c4652517`.
- Do not change corpus records, prompts, model identity, decoding settings, pricing,
  IVAD conditions, or candidate schema.
- Never persist raw rejected provider content, credentials, authorization headers,
  raw response IDs, or raw request IDs.
- No paid provider call occurs during implementation, tests, reconciliation, or
  local verification.
- Existing charge rows migrate to `accepted` without changing their totals.
- The released twentieth reservation is reconciled only at its frozen conservative
  upper bound `0.010542 CNY` and is labeled `rejected_estimate`.
- Resume is opt-in; without `--resume`, an existing candidate output remains an
  error.
- Only verified existing cells are skipped. Extra, tampered, or mismatched cells
  fail before provider I/O.
- No Qwen, matrix, formal run, paper update, remote push, tag, or release.
- Work inline in the existing linked worktree; the user explicitly declined
  subagent-driven implementation.

- [ ] **Step 3: Implement the generic policy**

Implement the module around this exact shape:

```python
class ProviderContentDisposition(StrEnum):
    ACCEPTED = "accepted"
    NORMALIZED_INVALID = "normalized_invalid"


class NormalizedProviderContent(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    content: str
    disposition: ProviderContentDisposition


class ProviderResponseContentPolicy(Protocol):
    def normalize(self, content: str) -> NormalizedProviderContent: ...


class JsonModelResponseContentPolicy:
    def __init__(self, schema: type[BaseModel]) -> None: ...
    def normalize(self, content: str) -> NormalizedProviderContent: ...
```

`normalize` must `json.loads`, cast to `JsonValue`, call
`sanitize_diagnostic_value`, reject any changed/redacted payload, validate the exact
Pydantic schema, and return `canonical_json(validated.model_dump(mode="json"))`.
Catch JSON, Pydantic, Unicode, type, and sanitization failures without including the
raw content in errors. Return the fixed invalid result instead of raising.
